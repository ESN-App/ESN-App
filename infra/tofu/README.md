# OpenTofu: Hetzner PoC and the `poc` environment

Manages: Hetzner server `esn-poc` (hel1), primary IPv4, firewalls `esn-poc-web` and `esn-poc-ssh-ci`, the deploy SSH key and the server SSH host key (generated), and on the repository side the `poc` environment (only branch `hetzner` may deploy) with the secrets and variables `poc-deploy.yml` reads. Passwords and keys are generated by tofu, so the state holds secrets: it is always encrypted (`enforced = true`) and committed only to the `infra-state` branch.

Not managed (never enter state, set by hand): `HCLOUD_TOKEN`, `TOFU_STATE_PASSPHRASE`, `TOFU_GITHUB_TOKEN`, `SMTP_USERNAME`, `SMTP_PASSWORD`.

## Bootstrap (once)

1. Hetzner: a project token with Read & Write (`HCLOUD_TOKEN`) and your personal SSH key already uploaded to the project (its name goes into `OWNER_SSH_KEY_NAME`).
2. Fine-grained personal access token limited to this repository with permissions: Environments RW, Secrets RW, Variables RW, Metadata R (`TOFU_GITHUB_TOKEN`).
3. Choose a state passphrase, 16+ characters, letters and digits only (`TOFU_STATE_PASSPHRASE`). Losing it means losing the state.
4. Repository secrets: `HCLOUD_TOKEN`, `TOFU_STATE_PASSPHRASE`, `TOFU_GITHUB_TOKEN`. Repository variables: `OWNER_SSH_KEY_NAME`, `SEED_ADMIN_EMAIL`, `EMAIL_FROM_ADDRESS`; optional `ADMIN_SSH_CIDRS` (JSON list, e.g. `["203.0.113.7/32"]`) and `POC_REVIEWER_USER_IDS` (JSON list of numeric user ids).
5. Environment `infra` with a required reviewer (it gates `apply`; `poc` is created by tofu itself).
6. Actions, workflow `Infra`, Run workflow on branch `hetzner`, action `apply`. Pushes touching `infra/tofu/**` run `plan` automatically.

## Local use

```bash
export HCLOUD_TOKEN=...  GITHUB_TOKEN=<TOFU_GITHUB_TOKEN value>
export TF_ENCRYPTION='key_provider "pbkdf2" "main" { passphrase = "<passphrase>" }'
git fetch origin infra-state && git worktree add .state origin/infra-state   # from the repo root
cd infra/tofu && cp terraform.tfvars.example terraform.tfvars               # edit
tofu init && tofu plan
```

The state in `.state/terraform.tfstate` is encrypted; only tofu with the passphrase reads it. After a local `apply`, commit and push `.state` to `infra-state` yourself, and do not run it while the workflow runs. Never use `tofu show` or `tofu output -json` in shared logs.

## If the state is lost

Rebuild by importing (the passphrase is still required for new state):

```bash
tofu import hcloud_primary_ip.v4 <primary-ip-id>
tofu import hcloud_firewall.web <id>; tofu import hcloud_firewall.ssh_ci <id>
tofu import hcloud_server.poc <id>; tofu import hcloud_ssh_key.deploy <id>
tofu import github_repository_environment.poc ESN-App:poc
```

Generated keys and passwords cannot be imported: the next apply creates new ones and overwrites the `poc` secrets (the new deploy key is not on the existing server, so rebuild it or add the key by hand).

## Changing the server type

Change `server_type` (e.g. `cpx02` to `cpx12`) and apply. The server resource has `keep_disk = true`, so the disk is not enlarged and a resize can be reverted. The server must be stopped and restarted by the provider, and `delete_protection`/`rebuild_protection` stay on. Changing cloud-init, image or SSH keys is deliberately ignored: do it as an explicit rebuild (`tofu apply -replace=hcloud_server.poc` after lifting protection; the primary IP and its `sslip.io` domain survive).
