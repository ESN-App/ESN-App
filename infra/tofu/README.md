# OpenTofu: Hetzner PoC and the `poc` environment

Manages: Hetzner server `esn-poc` (hel1), primary IPv4, firewalls `esn-poc-web` and `esn-poc-ssh-ci`, the deploy SSH key and the server SSH host key (generated), and on the repository side the `poc` environment (only branch `hetzner` may deploy) with the secrets and variables `poc-deploy.yml` reads. Passwords and keys are generated by tofu, so the state holds secrets: it is always encrypted (`enforced = true`) and committed only to the `infra-state` branch.

Not managed (never enter state, set by hand): `HCLOUD_TOKEN`, `TOFU_STATE_PASSPHRASE`, `TOFU_GITHUB_TOKEN`, `SMTP_USERNAME`, `SMTP_PASSWORD`. Your own SSH key (`OWNER_SSH_KEY_NAME`) is also added to the `deploy` user, because root login is disabled.

## Bootstrap (once)

The repository is public and `hetzner` is not protected, so the gate is the `infra` environment. Create it BY HAND before the first run: Settings, Environments, New environment `infra`, required reviewer (prevent self-review if you can), deployment branches = selected branches, `hetzner` only. GitHub auto-creates a missing environment without any protection, so never let the workflow do it.

1. Hetzner: use a DEDICATED project for the PoC (a token is project-wide, so it can touch everything in the project). Create a Read & Write token and upload your personal SSH key to the project (its name goes into `OWNER_SSH_KEY_NAME`).
2. Fine-grained personal access token limited to this repository: Environments RW, Secrets RW, Variables RW, Metadata R (`TOFU_GITHUB_TOKEN`).
3. State passphrase: `openssl rand -hex 32`. Losing it means losing the state.
4. Environment `infra` secrets: `HCLOUD_TOKEN`, `TOFU_STATE_PASSPHRASE`, `TOFU_GITHUB_TOKEN`. Environment `infra` variables: `OWNER_SSH_KEY_NAME`, `SEED_ADMIN_EMAIL`, `EMAIL_FROM_ADDRESS`, `POC_REVIEWER_USER_IDS` (JSON list of numeric user ids, required: the deploy key is root-equivalent on the server, so `poc` always has reviewers); optional `ADMIN_SSH_CIDRS` (JSON list), `STATE_REPO` and `STATE_BRANCH` (default: this repo, `infra-state`; secret `STATE_TOKEN` with contents write when `STATE_REPO` is another repository).
5. Push to `hetzner` touching `infra/tofu/**` (or run workflow `Infra` on `hetzner`): the `check` job (no secrets) runs, then `plan-apply` waits for approval, then runs init, plan and apply and commits the encrypted state.
6. Protect the state branch with a ruleset: no force-push, no deletion, restrict updates to the Actions bot. Anyone who can push the state branch can corrupt it; anyone who can push `hetzner` can change what apply does, which is why `infra` needs a reviewer.

## Rotation

Changing `TOFU_STATE_PASSPHRASE` re-encrypts nothing by itself. The old state can be read only with the old passphrase and the generated secrets in it are already exposed to whoever held it, so rotate those as well:

```bash
tofu apply -replace=random_password.postgres -replace=random_password.jwt -replace=random_password.seed_admin \
  -replace=tls_private_key.deploy -replace=tls_private_key.host
```

(The new deploy key must be added to the server, e.g. via a rebuild.) To change the passphrase only, run once with `TF_ENCRYPTION` containing both providers using the `fallback` block (see the OpenTofu docs on key rotation), then drop the old one.

## Local use

```bash
export HCLOUD_TOKEN=...  GITHUB_TOKEN=<TOFU_GITHUB_TOKEN value>
export TF_ENCRYPTION='key_provider "pbkdf2" "main" { passphrase = "<passphrase>" }'
git fetch origin infra-state && git worktree add .state origin/infra-state   # from the repo root
cd infra/tofu && cp terraform.tfvars.example terraform.tfvars               # edit
tofu init && tofu plan
```

The state in `.state/terraform.tfstate` is encrypted; only tofu with the passphrase reads it. After a local `apply`, commit and push `.state` to `infra-state` yourself, and do not run it while the workflow runs. Never use `tofu show` or `tofu output -json` in shared logs. `poc-deploy.yml` also needs `HCLOUD_TOKEN` as a secret of environment `poc` (it cannot read `infra` secrets); use a separate firewall-only token if you prefer.

## If the state is lost

Rebuild by importing (the passphrase is still required for new state):

```bash
tofu import hcloud_primary_ip.v4 <primary-ip-id>
tofu import hcloud_firewall.web <id>; tofu import hcloud_firewall.ssh_ci <id>
tofu import hcloud_server.poc <id>; tofu import hcloud_ssh_key.deploy <id>
tofu import github_repository_environment.poc ESN-App:poc
```

Generated keys and passwords cannot be imported: the next apply creates new ones and overwrites the `poc` secrets (the new deploy key is not on the existing server, so rebuild it or add the key by hand).

## Changing the server type

Change `server_type` (e.g. `cpx02` to `cpx12`) and apply. The server resource has `keep_disk = true`, so the disk is not enlarged and a resize can be reverted. The server must be stopped and restarted by the provider, and `delete_protection`/`rebuild_protection` stay on. Changing cloud-init, image or SSH keys is deliberately ignored: do it as an explicit rebuild (`tofu apply -replace=hcloud_server.poc` after lifting protection; the primary IP and its `sslip.io` domain survive).
